# PACE 基础批次（十二）：运行时检索臂的端到端 Δ（把向量通道的收益传到答案层）

日期：2026-09-15。范围：续批次十一。批次十一在**检索层**观察到向量通道的收益
（recall 0.94 → 0.98、coverage 0.957 → 0.9627），但那一层不是终点。

## 1. 为什么必须先造这条臂

`benchmark/baseline/prenatal_rag_client` 的 B1 是**冻结上下文设计**：模块 docstring
第一句写明"复用冻结的 B0 检索上下文，不重跑索引/检索"。这个设计对"隔离条件处理
效应"是正确的（同检索、只在检索与生成之间插入过滤），但它有一个直接后果：

> **任何检索侧的改动都无法通过 B1 被观测到。**

因此批次十一不能靠"把向量通道接进 B1"来拿生成层证据——那样做上下文一条都不会变。
要让检索层的 Δ 传到答案层，必须新增一条**真的按通道重检索再生成**的评估臂。

## 2. 实验设计：只差一个变量

同 50 题、同一证据真值层、同一 `k=16`、同一生成器与同一套提示词（
`build_generation_messages`，即 `[E1..En]` 编号 + 来源标识）、同一 judge，唯一差别
是 RRF 的通道列表：

| 臂 | 通道 | 候选空间 |
|---|---|---|
| `two_channel` | BM25 + 图通道 | 真值层锚点 |
| `three_channel` | BM25 + 图通道 + **向量通道** | 真值层锚点 |

两臂同空间、逐题配对（paired），只隔离"有没有第三条通道"这一个变量；不据此对
整套检索栈下跨架构结论。打分复用 `evaluate.score_arm`（本批把该函数从私有
`_score_arm` 提升为公开名并导出，以保证**只有一套打分实现**，避免第二次口径漂移——
批次十一刚因口径问题被自己抓过一次）。

## 3. 结果：检索层的收益**没有**转化为答案层的收益

50 题双臂、逐题配对（`answers_differ` **50/50**，即两臂答案全都不同）：

| 臂 | final | precision | recall | coverage | faithfulness | completeness | correctness |
|---|---|---|---|---|---|---|---|
| `two_channel` | 0.8812 | 0.7812 | 0.94 | 0.957 | **0.981** | **0.7546** | 0.8788 |
| `three_channel` | **0.8823** | **0.8263** | **0.98** | **0.9627** | 0.965 | 0.7412 | **0.8944** |

配对 Δ（三通道 − 两通道）：

- `final_score` **+0.0011**（25 题改善 / 21 题变差）——**与噪声无异**；
- `answer_correctness` **+0.0156**（22 / 17）；
- `faithfulness` **−0.016**（10 / 14）；
- `completeness` **−0.0134**（16 / 18）。

检索三项指标（P/R/C）全部改善，与批次十一的离线消融一致；但**最终分不动**，且在
生成侧呈现明确的**取舍**：correctness 升、faithfulness 与 completeness 略降。

### 为什么不动：天花板效应（分解到题）

- 50 题里**只有 2 题**的 recall 有提升空间：
  `PU-L3-024` R 0.0 → 1.0，final **+0.1239**（向量通道确实捞回了缺失的金标准源）；
  `PU-L4-001` R 0.0 → 1.0，但 final **不变**（该题 correctness 本就是 0.96、
  completeness 触底，属**地板效应**——召回补上也无处可涨）。
- 其余 **48 题**两臂 recall **完全相同**（0.94，都已命中金标准）；这 48 题的
  final Δ 均值是 **−0.0014**。

即：+0.04 的 recall 收益**集中在 2 道题**（该 2 题均值 +0.0620），而"换掉 16 条
上下文"让**全部 50 题**的答案都变了（50/50），两侧净效应互相抵消。

**结论**：当 recall 已接近天花板（0.94）时，**再加一路召回不构成答案层的改进理由**。
本批的检索层 Δ 真实、可复现，但其**可转化空间只有 2 题**——这正是一条"层 N 优化
不自动抬高层 N+1"的实例，也说明后续该做的是**候选池对齐与上下文取舍**（条件过滤
前置、同等分数下取哪 16 条），而不是继续堆通道。

参照：`two_channel` 的 final 0.8812 与批次十冻结 B0 受控重生成的 0.8795 基本持平，
即"真值层锚点空间的两通道检索"在答案层与冻结的 LightRAG 上下文**同档**。

## 4. 门禁 / EVIDENCE

- **真实判定运行**：50 题 × 2 臂 × (1 次生成 + 1 次评判) = 200 次 API 调用，
  `--judge-mode required`，judge 模型 `gpt-5`，约 50 分钟；产物含两臂**全部答案**
  与逐题分数（233 KB），可事后审计；
- **测试**：非 baseline 全量 **518**（含 baseline 547；prenatal 子集 406）——本批
  未加新测试，改为把新臂的**接线**纳入门禁（见下）；同时把 `evaluate.py` 的三处
  打分辅助函数由私有提升为公开（`score_arm` / `arm_score` / `arm_summary`）并从包
  `__init__` 导出，使**打分实现只有一套**（避免第二套口径——批次十一刚因口径吃过
  一次亏）；全仓无残留旧私有名引用；
- **ruff** 0 警、**pyright** 0 错 0 警；
- **覆盖率 8 段全部 100%**：conditions 298 / rrf 21 / evidence 155 /
  version_citations 71 / graph 99 / bridge 46 / pipeline 69 / vectors 96；
- **变异 49/49 全击杀**、**缓存哨兵 OK**；
- **真实执行 10 段**：新增第 10 段为端到端两臂的**接线 dry-run**
  （`--dry-run --limit 3`，stub 生成器 + judge off = **零 token**），并把 `--out`
  指向 `.gauntlet_tmp`，确保门禁**不会覆盖**真实判定结果（已核验：真实产物仍是
  `n=50 / judge_mode=required` 的那一份）；
- 命令：`bash benchmark/report/oldcoder_gauntlet.sh`（EXIT=0，`ALL LAYERS PASS`）。

## 5. 下一步（按本次结果重排优先级）

1. **候选池对齐**（由本批结果直接推出）：两臂 recall 在 48/50 题上完全相同，说明
   瓶颈已不在"召回得到"，而在"同等分数下取哪 16 条上下文"。应先做条件过滤前置与
   去冗余（同一来源多片段挤占预算），而不是继续加通道；
2. `PU-L4-001` 式的**地板效应**值得单独查：召回补齐但 completeness 触底，说明该题
   的 must-have 陈述无法从现有语料支撑，属数据/语料问题而非检索问题。

## 6. 本批最重要的结论

> 层 N 的指标改善**不自动**抬高层 N+1。本批的检索层 Δ（recall +0.04）真实、
> 可复现、且方向正确，但它能落地的空间只有 **2 道题**，最终分 +0.0011（噪声级），
> 且伴随 faithfulness/completeness 的轻微回退。若只汇报"检索指标变好"，会得出
> 一个**错误的产品结论**。
