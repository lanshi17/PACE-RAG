# S 变体离线检索对比（2026-10-12，零 token）

> S 冻结流程第一步（预注册 §6.2）：在开发集上离线比较 S 候选的检索指标。
> MMR 需要逐候选向量与逐对余弦计算，待实现；先比较 A11 vs S_metadata vs A00。

## 1. 设计

- A11：前置过滤 + 来源去冗余（R1 v2，62 题 × 3 重复均值口径下的检索层）
- S_metadata：同 A11 的 Inapplicable 集合，但**补位**（池内按 RRF 序取 top-16）
- A00：无过滤无去冗余（纯 RRF top-16）
- 指标：gold-source recall（对 62 题的 gold_sources.guide）

## 2. 结果（62 题）

| 配置 | gold-source recall |
|---|---:|
| A11（前置+去冗余，不补位） | **0.8468** |
| S_metadata（过滤+补位） | 0.8145 |
| A00（无过滤无去冗余） | 0.8145 |

## 3. 解读

1. **A11 的去冗余提高了 gold-source recall**（0.8468 vs 0.8145）：删除同源
   重复让预算让给了其他来源，捞回更多 gold 来源。
2. **补位抵消过滤收益**：S_metadata（过滤+补位）= A00（无过滤）——补位把
   Inapplicable 剔除后的空位用池内剩余候选填满，而池内剩余候选的 gold 命中
   率不高于原 top-16。**"过滤+补位"不是有效的简单对照**。
3. **与 R1 v2 final 的矛盾及解释**：R1 v2 显示 A11−A10（去冗余）≈ 0，但
   离线 gold-source recall 显示 A11 > 补位变体 +0.03。两个口径不同：
   gold-source recall 衡量"来源集合覆盖"，final 衡量"答案质量"——
   来源覆盖提升没有传导到答案质量（上下文内容重叠、Judge 评分对来源多样性
   不敏感）。这本身是一个可报告的发现：**检索层覆盖提升 ≠ 生成层收益**
   （再次印证批次十二的结论）。

## 4. 对 S 冻结的影响

- metadata filter（补位）作为 S 候选**无检索层优势**——排除。
- 剩余 S 候选：**MMR**（需逐候选向量，待实现）；S 冻结需 MMR 离线对比后决定。
- 若 MMR 也无检索层优势，S 退化为 A11 本身（去冗余作为"强简单对照"），
  H2 主比较变为 P vs A11。
